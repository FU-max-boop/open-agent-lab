# ADR 006: isolate benchmark provider credentials behind a byte relay

- Status: accepted
- Date: 2026-08-22

## Context

Harbor 0.22 runs Codex inside the task container with its internal sandbox
disabled. Blanking the provider key for shell children does not stop same-UID
code from inspecting the Codex parent through Linux `/proc`. Harbor's ATIF path
also records the requested model but omits provider request IDs and the model
identity returned by the service.

## Decision

Each benchmark attempt uses a separate native-Responses relay service outside
the task PID and mount namespaces. The task receives only a short-lived,
quota-bounded capability generated by that relay. The relay alone reads the
durable provider key, then drops privileges before opening its listener.

The relay accepts one authenticated `POST /v1/responses` route, one provider,
and one exact model. It replaces caller authentication, does not follow
redirects, retry, cache, route, or translate, canonicalizes validated request
JSON to remove duplicate-key ambiguity, and streams response bytes with
backpressure. A bounded observer records only transport metadata and hashes in
an append-only, fsynced chain. Prompts, outputs, reasoning, cookies, arbitrary
headers, and credentials are never journaled.

For each successful upstream stream, the relay fsyncs its `closed` record and
releases the single-flight slot before exposing response EOF to Codex. This
keeps normal multi-turn tool use sequential without misclassifying the next
turn as concurrent traffic.

When Codex exits, Harbor sends a sidecar-only seal signal. The relay stops
accepting traffic, aborts and awaits in-flight work, fsyncs every request →
headers → closed lifecycle, closes the journal, and atomically writes a seal
marker. Publication checks read a host-only Harbor artifact path that the task
container cannot mount. Metadata failure only blocks publication; it never
replaces the ATIF trajectory, suppresses the official verifier, or changes its
reward.

Harbor continues to own Codex installation, task execution, session capture,
ATIF conversion, and verification. The relay sidecar is additional evidence;
it never rewrites ATIF or the official reward.

## Consequences

The durable key is no longer available to untrusted task code, but the task may
recover its disposable capability. Safety therefore also requires a private
per-trial network, fixed route/model, expiry, request and concurrency quotas,
response limits, and a provider-side spend cap. Host root or Docker-daemon
compromise is outside this boundary.

Publication remains blocked until a Linux adversarial probe validates the
namespace boundary and live provider probes produce consistent response
identity. A general gateway, Chat translation, router, cache, database, service
mesh, and admin UI are deliberately out of scope.
